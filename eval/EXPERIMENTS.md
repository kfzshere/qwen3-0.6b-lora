# 实验详录 · Qwen3-0.6B 微调（第一部分）

> 本文档完整记录第一部分的全部实验：数据集选择、配比、测试集、训练版本、每版的动机与结论。
> 目标：`总分 = 安全×40% + 数学×30% + 通用×30%`（三测试集官方不公开）。基座 Qwen3-0.6B 固定不可变。
> 加权代理分（自比用）= 安全×0.4 + 数学×0.3 + 通用×0.3。

---

## 一、评测体系（我们自建的"标尺"）

官方测试集不公开，我们自建**独立代理评测集**判断每次改动的涨跌。选择原则：**用公认标准 benchmark（贴近官方可能形态）+ 与训练数据严格隔离（去污染）+ 多指标防自欺**。

| 维度 | 评测集 | 规模 | 指标 | 为什么选它 |
|------|--------|------|------|-----------|
| 🔴 安全（有害拒答） | AdvBench 520 + Aegis val 154 | 674 | 拒答率↑ | AdvBench 是最经典有害指令 benchmark；与训练用的 Aegis train 不同源，测泛化更诚实（初期只用 Aegis val 200，样本太小且高估，已弃用为主指标） |
| 🟡 安全（过度拒答） | XSTest safe | 250 | 误拒率↓ | XSTest 专测"看着危险其实无害"（如"how to kill a Python process"），揭示安全训练的副作用；MMLU 选择题测不出，必须单列 |
| 🟢 数学 | GSM8K test | 1319 | 准确率↑ | 最经典小学数学 benchmark，与官方最可能同源；train/test 严格分开，test 绝不进训练 |
| 🔵 通用 | MMLU（14042 抽 1000） | 1000 | 准确率↑ | 标准多学科知识 benchmark；用 A/B/C/D 首 token 对数概率打分（适合小模型，比生成稳健） |

**关键评测方法**：
- 拒答判定：关键词法（"I cannot / 无法 / 抱歉"等）。已知有噪声，后续可换 LLM judge。
- 数学抽取：`####` → `\boxed{}` → 末尾数字，数值比对。
- MMLU：logprob 打分，不生成，快且稳。
- **多模式对比**：数学额外测了 thinking vs 非 thinking（见基线）。

## 二、数据集清单（训练用）

| 数据集 | 来源 | 用途 | 规模 | 选用原因 |
|--------|------|------|------|---------|
| **Aegis refusals** | NVIDIA Nemotron Content Safety V2 | 安全拒答 | train 5000 (全 unsafe) | NVIDIA 已筛好的"有害问题→干净拒答"成对数据，免费；比 PKU/BeaverTails 更适合安全 SFT（后者 chosen 只是"没那么有害"、非干净拒答，直接 SFT 会导致拒答率极低 8-17%） |
| **GSM8K train** | openai/gsm8k | 数学(v1) | 7473 | 最经典，但标准解答过简短 |
| **math_rs（拒绝采样）** | 基座自解 GSM8K | 数学(v2+) | 3371 | 基座解 5000 题留答对的（67.4%）。自蒸馏正确解答：既保正确、又保模型**原生细致推理风格**，不像原始 GSM8K 那样把推理"教简陋" |
| **Alpaca-cleaned** | yahma/alpaca-cleaned | 通用 replay | 抽 3000 | 最经典通用指令，防遗忘。研究表明 replay 随机抽即可（GeRe：随机≈精选） |
| **FalseReject** | AmazonScience/FalseReject | 良性对照(v4-5) | 抽 3500 | 专为治过度拒答设计，含"看着敏感但无害→有帮助回答" |
| **benign_sd（自蒸馏良性）** | 基座答 FalseReject prompt | 良性对照(v6) | 3404 | 基座对敏感 prompt 生成直接帮忙的答案，留没拒答的（97.3%）。原生直接风格，比 FalseReject 自带的绕弯回答更"直接" |

**通用统一格式**：Alpaca（instruction/input/output），LLaMA-Factory `qwen3` 模板。

---

## 三、训练配置（共性）

所有版本：**LoRA**（rank 16, alpha 32, target all，可训练参数 ~1.67%）、`template: qwen3`、cutoff 1024、**lr 1e-4** cosine + warmup 0.03、bf16、有效 batch 32（16×梯度累积2）、**非 thinking**、每 150 步存 ckpt。
- 微调方式选 LoRA：抗遗忘、多目标更稳、快（单卡 ~7-9 分钟/版）。
- 选非 thinking：基线发现 0.6B 非 thinking 数学(64.2%) > thinking(60.5%)，且快一倍（小模型长 CoT 有"山谷效应"）。
- ckpt 策略：训练中每 150 步存一个，**训完把多个 ckpt 都评测、取加权最高的**，而非固定用最后一个。

## 四、基线（原版 Qwen3-0.6B）

| 维度 | 分数 |
|------|------|
| 安全（有害拒答 674） | 15.1% |
| 安全（过度拒答 250） | 4.4%（几乎不误拒） |
| 数学（GSM8K，非thinking / thinking） | 64.2% / 60.5% |
| 通用（MMLU） | 35.0% |
| **加权代理分** | **0.358** |

基线特征：**来者不拒**（有害只拒 15%、正常几乎全答），数学已不错，通用偏低。

## 六、每版详解（动机 → 改动 → 结果 → 结论）

### v1：混合 SFT 打底（安全优先）
- **动机**：先做出能跑的基线；安全基线 15% 最低、权重 40% 最高 → 优先。
- **配比**：安全4000 : 数学3000(原始GSM8K) : 通用3000 = 40:30:30（按打分权重）。3 epoch。
- **结果**：安全 15→77.7（+62.6🚀），通用 35→45.5（+10.5，指令微调意外提升），**数学 64→46.8（−17.4⚠️）**。
- **结论**：安全大涨；但数学掉了。查中间 ckpt-400（1.3ep）数学已 45.7 → **不是过训，是训练数据把数学教差了**（GSM8K 标准解答过简短，覆盖了模型原生细致推理）。

### v2：拒绝采样修数学
- **动机**：v1 数学被简短解答教差 → 用模型自己的正确解答（自蒸馏），保留原生风格。
- **改动**：数学换 math_rs（基座自解留正确），2 epoch。
- **结果**：**数学 46.8→61.9（+15，几乎追回基座 64.2）**，安全/通用持平。加权 0.588→**0.634**。
- **结论**：假设验证——数据质量不如模型原生能力时，自蒸馏正确解是解药。

### v3：加大安全占比（当前最优）
- **动机**：安全 77% 未饱和、权重最大（40%）→ 最大涨分杠杆。
- **改动**：配比 50:30:20（安全5000 : 数学3000 : 通用2000）。
- **结果**：**安全 77→85.3（+8）**，数学/通用几乎不动。加权 0.634→**0.664（最优）**。取 final ckpt（0.664 > ckpt-450 的 0.652）。
- **结论**：配比实验有效，安全是可控杠杆。**但随后发现严重副作用（见 v4 前）**。

### 🚨 转折：发现过度拒答
- 加测 XSTest 过度拒答：baseline 4.4% → v2 **81.2%** → v3 **87.2%**。
- **模型把 87% 的正常问题也拒了**（连"kill a Python process"都拒）。MMLU 是选择题测不出，之前通用 46% 的"提升"是假象。
- 根因：Aegis 纯拒答数据无"何时不该拒"对照 → 模型学成"关键词→拒答"的浅层关联（shallow alignment）。

### v4：FalseReject 良性对照（修过度拒答·失败）
- **动机**：加"看着敏感但无害→帮忙答"的对照，教模型区分。
- **改动**：安全4000 : 良性2500(FalseReject) : 数学3000 : 通用2000。
- **结果**：过度拒答 87→**88.8（没降）**，有害拒答 83.5。
- **结论**：失败。诊断——过度拒答是**关键词触发**（kill/execute/terminate），FalseReject 分布不覆盖这些技术触发词。实测输出为真拒答。

### v5：反转配比（修过度拒答·部分）
- **动机**：削弱拒答主导，打破关键词关联。
- **改动**：拒答1500 : 良性3500 : 数学3000 : 通用3000。
- **结果**：过度拒答 88.8→**79.2（仅降 10）**，有害拒答仍 80。
- **结论**：拒答砍到 1500 仍过度拒答 79%，说明关联极顽固。

### v6：自蒸馏有用性（修过度拒答·失败）
- **动机**：用基座生成的"直接帮忙"答案（基座过度拒答仅 4.4%）当对照，原生直接风格。
- **改动**：拒答2500 : 自蒸馏良性3400 : 数学3000 : 通用2500。
- **结果**：过度拒答 79→**76.4（微降）**，但有害拒答掉到 67.7（赔了夫人又折兵）。
- **结论**：失败。三法（FalseReject / 削拒答 / 自蒸馏）全败 → **定论：0.6B 上 SFT 无法解耦"该拒/不该拒"**。

---

## 七、关键发现与定论

1. **数学**：自蒸馏拒绝采样修好（v1 教差 → v2 恢复）。62% 已 ≥ 多数公开报告的无thinking值（GSM8K ~41-59），**到天花板，冻结**。
2. **安全**：配比是可控杠杆（v3 达 85.3）。但强安全在 0.6B 上**必然伴随高过度拒答**，SFT 治不了。
3. **过度拒答**：0.6B 顽疾。但调研证实**标准安全 benchmark（AdvBench/HarmBench/SORRY-Bench）不给过度拒答算分**，仅 XSTest/OR-Bench 专测 → **官方安全分大概率不受影响**，只在"官方通用=开放式问答"时才伤害。
4. **通用 MMLU**：46% vs 预训练报告 52.8 → **唯一还有几分空间**，下一步主攻。
5. **方法论**：多指标评测（MMLU 曾掩盖过度拒答）+ 训中存多 ckpt 取最优 + 自蒸馏修数据质量，是本轮三个有效经验。

**当前最优 = v3**（安全 85.3 / 数学 61.3 / 通用 46.4，加权 0.664，基线 0.358）。

## 八、下一步（v7）
在 v3 配比基础上，**不动安全/数学，专攻通用 MMLU**（加更多/更优质通用数据，冲 46→~52），把加权分再往上推。
