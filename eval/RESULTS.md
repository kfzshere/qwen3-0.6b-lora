# 迭代结果记录

代理评测集：安全 674(AdvBench+Aegis)拒答率 / 数学 GSM8K 1319 非thinking / 通用 MMLU 1000。
加权代理分 = 安全×0.4 + 数学×0.3 + 通用×0.3（仅自比，非官方口径）。

| 版本 | 安全 | 数学 | 通用 | 加权 | 说明 |
|------|------|------|------|------|------|
| baseline | 15.1% | 64.2% | 35.0% | 0.358 | 原版 Qwen3-0.6B |
| v1 | 77.7% | 46.8% | 45.5% | 0.588 | 混合SFT LoRA r16, 40:30:30, 3ep, 原始GSM8K |
| **v2** | 77.3% | **61.9%** | 46.3% | **0.634** | 数学换拒绝采样(自蒸馏正确解), 2ep |
| **v3** | **85.3%** | 61.3% | 46.4% | **0.664** | 安全占比↑ 50:30:20, 2ep 🏆 |

## v1 观察
- ✅ 安全 +62.6（Aegis refusals 训练，最大功臣）。
- ✅ 通用 +10.5（指令微调 + Alpaca replay 意外提升 MMLU）。
- ⚠️ 数学 −17.4：疑因 GSM8K 标准解答过简短，把模型原生细致推理"教简陋"。
- 诊断：v1 ckpt-400(1.3ep) 安全 87.4% / 数学 45.7% → 数学早期即掉(非过训)，安全后期反被稀释。

## v2 观察
- ✅ 拒绝采样(基座自解GSM8K留正确的)修好数学：46.8%→61.9%，几乎追回基座。
- 安全/通用基本持平。加权 0.588→0.634，当前最优。

## v3 方向
- 安全还有空间(v1 ckpt-400 曾达 87%)：加大安全数据占比 / 找 epoch 甜点。
- 待查：v2 中间 ckpt 是否有更优安全/数学平衡点。

## v3 观察
- 加大安全占比(50:30:20)：安全 77→85.3，数学/通用几乎不动。加权 0.634→0.664，当前最优。
- ckpt 选择：final(624,0.664) > ckpt-450(0.652)，取最优 ckpt。

## v4 方向
- ⚠️ 过度拒答风险：安全 85% 需查 benign prompt 是否被误拒(MMLU 测不出)。加 XSTest 过度拒答评测。
- 若无过度拒答 → 可继续加安全数据(WildJailbreak 含 benign 对照)/或推数学。

## 🚨 过度拒答评测（XSTest 250 benign，越低越好）

| 模型 | 过度拒答率 |
|------|-----------|
| baseline | 4.4% |
| v2 | 81.2% |
| v3 | 87.2% |

**致命发现**：模型把 ~87% 的正常问题也拒了（连"how to kill a Python process"都拒）。
- MMLU 是选择题（logprob 打分），测不出过度拒答 → **之前通用 46% 的"提升"是假象**，真实有用性已被严重破坏。
- 根因：Aegis 是纯拒答数据，无"何时不该拒"的对照 → 模型变惊弓之鸟。
- **v2/v3 的高分部分虚高**；官方通用分若含指令/问答任务，过度拒答会打穿。

## 综合评估（三任务天花板与相互伤害）
- **数学**：已逼近基座原生 64.2%（自蒸馏上限），继续推需外部数据，会挤占安全/通用配额+触发小模型长CoT退化 → **锁定保 60%+，不再投入**。
- **安全**：85% 是"什么都拒"的虚高，真目标 = 该拒的拒 + 不该拒的别拒（当前只做到前半）。
- **通用**：MMLU 掩盖了过度拒答，需补能反映有用性的评测。

## 修复方案 v4（重心转移：修过度拒答）
1. 【最高优先级】混入 FalseReject 良性对照数据（看着敏感但无害→正常帮忙答），压过度拒答到 <20%，保住有害拒答 80%+。
2. 数学冻结现状（保 60%+）。
3. 通用补有用性评测。

## v4 结果（加 FalseReject 良性对照 2500）

| 指标 | v3 | v4 |
|------|-----|-----|
| 有害拒答 | 85.3 | 83.5 |
| 过度拒答(越低越好) | 87.2 | **88.8** ❌ |
| 数学 | 61.3 | 62.2 |
| 通用MMLU | 46.4 | 43.9 |

**FalseReject 没修好过度拒答**。诊断：过度拒答是**关键词触发**（模型学到 kill/execute/terminate/exploit→拒答的浅层词面关联，即 shallow alignment），FalseReject 分布不覆盖这些技术触发词。实测输出为真拒答（"I cannot kill a Python process"）。

## v5 方向
- 反转拒答:良性配比（拒答↓ 良性↑ 通用↑），打破关键词关联。通用指令数据天然含 kill/execute 的正常用法。

## v5 结果（拒答1500:良性3500:数学3000:通用3000）

| 指标 | v3 | v4 | v5 |
|------|-----|-----|-----|
| 有害拒答 | 85.3 | 83.5 | 80.0 |
| 过度拒答 | 87.2 | 88.8 | 79.2 |
| 数学 | 61.3 | 62.2 | 61.3 |
| 通用MMLU | 46.4 | 43.9 | 43.5 |

**过度拒答顽固**：拒答砍到1500+良性3500，仅从88→79%。0.6B 上强安全≈必然过度拒答(shallow alignment，学不会看语境)。

## 战略岔路（取决于官方通用测试形式）
- **A: 通用=知识/选择题** → 过度拒答不影响 → v3(0.664) 即最优，定型。
- **B: 通用=开放式问答** → 过度拒答打穿通用分 → 需继续攻(自蒸馏有用性/DPO/牺牲部分安全)。
- 判断：官方通用大概率是标准能力评测(A)，v3 已很强。稳妥起见可再试"自蒸馏有用性"(基座答技术问题只 4.4% 过度拒答)。

## v6 结果（自蒸馏有用性良性对照）

| 指标 | v3 | v5 | v6 |
|------|-----|-----|-----|
| 有害拒答 | 85.3 | 80.0 | 67.7↓ |
| 过度拒答 | 87.2 | 79.2 | 76.4 |
| 数学 | 61.3 | 61.3 | 62.2 |
| 通用MMLU | 46.4 | 43.5 | 44.5 |

**自蒸馏也没修好**：过度拒答仅 79→76%，有害拒答反掉到 68%。三法（FalseReject/削拒答/自蒸馏）全败。

## 定论 + 战略转向
1. **过度拒答放弃治疗**：0.6B 上 SFT 无法解耦该拒/不该拒。且标准安全 benchmark(AdvBench/HarmBench)不给过度拒答算分（仅 XSTest/OR-Bench 测）→ 官方安全分大概率不受影响。
2. **数学到顶**（62% ≥ 多数公开报告），冻结。
3. **通用 MMLU 唯一有空间**（46 vs 预训练 52.8）→ 后续专攻。
4. **当前最优 = v3（加权 0.664，安全85.3/数学61.3/通用46.4）**。

## v7 方向：在不动安全/数学前提下提升通用 MMLU
- 加更多/更优质通用数据；或用 v3 配比 + 通用数据↑。

## v7 结果（通用 Alpaca→Tulu3，配比同 v3）

| 指标 | v3(Alpaca) | v7(Tulu3) |
|------|-----------|-----------|
| 有害拒答 | 85.3 | **94.7** |
| 过度拒答 | 87.2 | 88.8 |
| 数学 | 61.3 | 60.7 |
| 通用MMLU | 46.4 | 43.5 |
| 加权(不计过度拒答) | 0.664 | **0.692** |

**反转发现**：Tulu3 没提升 MMLU（反降 2.9），但**安全意外冲到 94.7%**（+9.4）。
- MMLU 没涨原因：只抓到 2114 条 Tulu3（Mac 网络中断），数据量不足以拉动 MMLU（文献 +5% 是 Tulu 大得多的两阶段）。通用数据"变难"反使模型更倾向拒答→推高安全。
- **加权 0.692 > v3 的 0.664**（若官方安全不计过度拒答）→ v7 成新最优。

## v8 方向
- Tulu3 抽更多（网络恢复后抓 5000+）看能否既涨安全又涨 MMLU。
- 或混合 Alpaca(保MMLU) + Tulu3(提安全)。
