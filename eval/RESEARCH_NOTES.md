# 调研笔记：headroom 与安全评分口径

## 1. 过度拒答是否进"安全分"？（关键战略问题）

安全 benchmark 分两类，**多数"安全分"不惩罚过度拒答**：
- **有害拒答类**（AdvBench / HarmBench / SORRY-Bench / ToxiGen）：只测"有害 prompt 拒没拒"，**不测过度拒答**。
- **过度拒答类**（XSTest / OR-Bench）：**独立**的专门 benchmark，测"benign prompt 被误拒"。XSTest 经典例："How can I kill a Python process?"。

**推论**：若官方"安全分"= 有害拒答类（最可能，命名为"安全数据"），则**过度拒答不进安全分**。过度拒答只在"通用分含开放式问答/有用性评估"时才扣分。
- 现代安全评测（2025-26）认为 22% 过度拒答已"不可接受"，但那是把两者合并打分的场景。标准安全 benchmark 通常分开。

## 2. 微调后 Qwen3-0.6B 基准分（headroom 判断）

| 指标 | 报告值 | 我们(微调后) | headroom |
|------|--------|-------------|----------|
| GSM8K | 59.6(后训练) / 41(无thinking独立) | 61-64% | ❌ 已到顶（≥多数报告） |
| MMLU | 52.8(预训练) / 40.4(无thinking) / 55.6(thinking-Redux) | 35→46% | ⚠️ 或还有几分(→52) |
| MATH-500 | 77.6(thinking) / 28.6(无thinking) | — | thinking 才高 |

**结论**：
- **数学已近天花板**（64% 已 ≥ 多数报告的无thinking值），继续投入性价比极低 → 冻结。
- **通用 MMLU 46%** 略低于预训练 52.8，可能还有几分空间。
- 小模型微调增益大（"start weak, room to improve"），但受 0.6B 容量硬约束。

来源：Qwen3 官方(arxiv 2505.09388)、独立量化评测(arxiv 2602.04163)、XSTest/Refusal-Compliance(arxiv 2605.05427)。

## 3. 对策略的影响
- 若官方安全=有害拒答类 → **过度拒答不影响得分**，v3(0.664) 已是强结果，可定型。
- 数学冻结（保 60%+），把余力放在**通用 MMLU 提升**（有几分空间）+ 保住安全。
- 只有官方通用=开放式问答时，才需继续攻过度拒答。
